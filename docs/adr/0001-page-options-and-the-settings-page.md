# 0001 — 设置页：选项槽、双写，和谁给 CSS 上色

Status: **Accepted**（2026-11-25）。

## 1. 三条需求，一个已有的机制

设置页要能改三样东西：线框模式（手绘边框）、主题（`core.css` 里的颜色与圆角变量）、以及"刷新之后还是我选的那样"。前两样看着像渲染器的事，其实 fluxen 已经把机制做完了，本仓要做的只是用它。

fluxen ADR 0038 §2 定的形状：**页面选项是一个槽里的一个对象**，槽名由 `#main[data-config]` 给（缺省 `__CONFIG__`，本仓的 `#main` 没写这个属性，所以就是缺省），成员**逐个**决定——页面自己那一半先，远侧（生产端）在后。§3 再给一条：生效的对象按**标量成员**镜像成文档根上的 `data-<member>` 属性，一个 effect、一个成员一条属性。线框是 `sketch` 成员：`true` 时渲染器自己用 roughr 画边框（§3-4），`normal` 时一个节点都不多。

所以这一轮**不新增帧、不改 fluxen**。设置页是三件事：把值写进那个槽、让值到得了服务端、让浏览器把 CSS 变量落下去。

## 2. 值怎么走：`scope: both`

写选项的出口是一个组的 `sink`，而 `Sink{dest, scope, path}` 里的 `scope` 决定这次写落在哪（ADR 0031 §1 的三个词，`Scope::Both` 的定义是"assigns locally and mirrors the change up"）。实现就在 `ui_core/src/ctx.rs:173` 的 `Ctx::emit`：`scope.local()` 时同步 `write_local_at(dest, path, payload)`——同一帧内改掉本地半边，镜像随之重画；`scope.remote()` 时 `spawn_local(ctx.send(dest, id, payload))`——上行一份。`both` 两条都跑。

`dest` 一个名字担两个角色：本地写进的那个槽名，和上行的目标名。两者都取 `__CONFIG__`，于是**"设置事件"与"config 事件"是同一条**，不需要第二个 dest 家族，也不需要把设置拆成另一种帧。

一个组只有一个出口（ADR 0032 §2），所以"本地立刻改"和"服务端记住"不可能靠两个 sink 拼出来——`both` 就是这条需求的唯一合法形状，不是折中。

## 3. 谁上色：fluxen 停在属性，reflux 的 runtime 落到自定义属性

镜像只给属性，而 CSS 读不到属性值——`attr()` 落不进 `var()`。所以"把值变成 `--accent` / `--round`"必须有人做，三条落法：

- **命名调色板**：值只发名字（`theme: "amber"`），`reflux.css` 里按 `html[data-theme="amber"]` 映射到令牌。不需要桥，但值不能任意——与"设置 css 中的颜色、圆角等变量"这条需求不符。它不冲突，将来要做成一组预设也只是往同一个成员里写名字，代码不动。
- **根节点的 `attrs.style`**（`{"--accent": "#c08a2e"}`）：渲染器原样写进 `style`（`frame.rs:201` 就是 `format!("{k}: {v};")`），自定义属性合法、子树继承，零 JS。但那个 `style` 是**绘制期拼出来的字符串**，不是响应式信号：改一次值就要服务端往返一次、重画那个节点。调一次圆角就是一帧，不可用。
- **决定：客户端 runtime 加一张表**。`www/static/reflux.js` 里放 `STYLE`，把 `data-<member>` 落到 `:root` 的 `--*`：`accent`（颜色，格式校验）与 `round`（0–24 整数，补 `px`）。值任意、改动即时（本地半边先写，镜像和上色在同一帧内完成）、没有往返。

它是客户端 runtime 的第五件事，排在前四件（握手、地址栏、标题、token）之后，而且**只读属性**：不看帧、不碰 socket——那条边界没有动。

## 4. 拦截的边界

`STYLE` 表是**闭集**，不是一个"任意属性 → 任意变量"的通路：表里没有的成员一概不碰。`sketch` 留给渲染器（它按 `data-sketch` 画边框，`--round` 还会被压成 0，因为形状归那张画），`theme` 留给 `reflux.css` 的 `html[data-theme=…]` 块（将来若做预设），将来别的成员归各自的层。

于是"CSS 相关的先由宿主 runtime 拦下，剩下的还是 fluxen 的"在浏览器侧成立，而 fluxen 一个 CSS 变量都不认识——`data-*` 是它能给到的极限，正好够。

## 5. 持久化：服务端是"新连接从哪开始"那份

上行到 `@app.on("__CONFIG__")` 的载荷是这一次改动的成员（组的打包对象）。处理器合并进应用自己的对象、按白名单与值域校验、落盘。落盘要节流：值真的变了才写，且短间隔内的连续改动只写最后一次——`submit=["change"]` 是每次按键一次上行。

页面每次绘制之前先 `set` 这个槽，于是新连接、刷新、换设备的第一帧就带着用户的选择，不会出现"默认 → 你的选择"那一闪。

两边不打架的依据在读侧：`hooks.rs:110` 是**成员逐个**、本地先。用户改了一个成员，本地半边就只多了那一个，其余成员仍读远侧；服务端回写的整个对象永远落在远侧，压不过页面自己选过的那一半。这就是 ADR 0038 "members are decided member by member" 的原意，本仓不需要另立规则。

## 6. 代价

- **`reflux.js` 从"不认识样式"变成认识一张表**。这是新契约，要写进 `docs/DESIGN.md` 的 I6 与 `HANDOFF`。prism 不复用这一段：它的页面是它自己的产物，要就用它自己的一段脚本——宿主适配渲染器，不是渲染器替宿主上色。
- **每次 `change` 一次上行**（输入框是每敲一下）。服务端因此要节流落盘；设置页只有几个控件，这个量可以接受，但"值一变就 fsync"是不行的。
- **一个组一个出口**，所以"只在本地改、不同步"这种设置项本仓没有；真需要时就把它从设置页里拿掉，别指望两个 sink。

## 7. 不做的事

- 不给 fluxen 加 `theme` 概念，也不让核心写 CSS 变量：核心到 `data-*` 为止（ADR 0038 §3 已经定过为什么——属性是 devtools 与 CSS 的公共面）。
- 不新增线上词汇：没有 settings 帧、没有新动作、没有第二个协议。
- 不把持久化放进框架：`App` 不碰磁盘，落盘属于示例应用（`--settings <path>`，缺省 `./.demo-settings.json`，入 `.gitignore`）。
- 不在 `reflux.js` 里做"任意属性 → 任意变量"：表就是白名单，校验也在表里。浏览器不是可信的一侧，服务端另有一道。
