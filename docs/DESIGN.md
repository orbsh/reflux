# Reflux — 设计

状态：方向已裁决 · 2026-10-16 · 仓库 `reflux`

Reflux 是**集成 fluxen 的 web 框架**：渲染是 fluxen 的事，reflux 是它外面那一层——页面、路由、会话、线、伺服、SDK、门。分工是 Next 之于 React 的那种。

- **词表的单一来源是 accrete 的类型**：fluxen 的线就是 accrete 的线，`cargo run -q -p stage -- schema` 把它导成 draft 2020-12 的 JSON Schema，各语言 SDK 由它生成，不手写第二份词表。
- **渲染器只有 fluxen 一个**：它的包由维护者构建一次、钉死版本伺服给消费方，消费方零工具链。页面路径、会话、线是 reflux 的事，不进那个包。
- **框架的客户端 runtime 很小**（握手、URL 与标题的镜像），作为独立文件挂在 fluxen 的包旁边——不自己渲染，也不进包。
- **服务端只持有它业务上需要的值**，并在事件边界接收组件随事件送上来的那一份状态。

已裁决退场的形态：把 reflux 做成「一份规格加一套自带词表的 SolidJS 壳」的那一版——自带词表的壳与手写的 `spec/components.json` 一起退场（判据见「Why Not」）。迁移落地前它们仍是现状（T0–T6 的门对着它们跑通），落地后按 `PLAN.md` 的迁移任务逐条换掉。

## 定位

- **用宿主语言写 UI**：开发者在自己的语言里写组件树、绑定与事件处理器。Python 起步；任何能发 JSON 的语言都能接——SDK 由 accrete 的类型导出的 schema 生成（见 I5）。
- **组件是粗粒度的**：线上传的是 `input`、`table`、`form`、`rack` 这类有语义的组件，不是 `div`/`span`。组件语义、元素映射、可访问性、本地行为（输入缓冲、展开、选中、校验）在渲染器里写一次；**哪些类型进应用面、哪个属性值是默认**由 reflux 的 profile 定——profile 是 accrete 那 30 个根变体上的逐项选择（见「组件词表」），两边不是包含关系：我们现在这 21 项里只有 8 项与它同名。
- **消费方零工具链**：资产是静态的（钉版本的 wasm 包加框架那一小段 runtime），消费方不用 npm、不用打包器、不用 wasm 工具链、没有构建步骤、运行时也不依赖 CDN。构建那一步只在维护者这边发生，一次。
- **服务端不画界面**：没有「服务端重渲染 + 全树 diff」这条默认路径（为什么否掉见「Why Not」）。服务端发的是**结构与数据**，界面由渲染器按组件语义自己画。

非目标：不做 SSR/hydration；不做离线客户端；不做通用 RPC；不做任意 HTML/JS 的通道——线上只有数据。

## 不变量

- **I1——线上是数据，不是代码。** 没有 eval、没有生产者下发的 JS、没有 HTML 字符串。给界面挂行为的只有渲染器自己的组件实现。
- **I2——更新是操作，不是快照。** 一帧携带针对客户端当前状态的操作增量（结构或数据）；除（重）连接那次，不重发整棵界面。
- **I3——词表封闭。** 组件集、每类型的属性集、事件集、操作集都收在 accrete 的类型里（闭枚举、穷举匹配），渲染器对全部类型有实现；reflux 侧是它上面的一份 profile——选哪些类型进应用面、默认值是什么、变体的闭集合落成哪些 class 令牌。扩展词表等于改那一处类型、重导一次 schema，没有运行时注册，也没有第二份手写词表。新的产品能力是既有词表上的新数据。**代价写明**：变体这类闭集合在 accrete 的属性空间里没有字段可放，只能收在 profile 的数据里、落成 class；这一层的封闭靠 profile 的数据、生成器的门与服务端入站校验，不再靠编译期类型。
- **I4——工作态住在前端；服务端只在事件边界拿到事件携带的那份。** 输入缓冲、展开、选中、表单暂存、焦点、滚动都是渲染器的。服务端要某份状态，就只能靠组件随事件把它送上来（**送什么由组件定**——输入送它的值、表单送它收集到的字段；我们旧形态里那份 `payload` 声明随裁决退场，见「操作」）——不允许出现「服务端悄悄持有一份界面工作态」这种影子状态。
- **I5——词表的单一来源是 accrete 的类型。** SDK 的类型层（类型、枚举、变体、必填与默认）由它导出的 schema 生成，构造器面在生成物上加一层薄的命名与手感；不手写第二份词表。N 个 SDK 手写 N 份词表，必然漂移。
- **I6——一个 socket 只有一套帧定义。** 就是 fluxen 那套（`Message` / `Content` / `Outflow`），reflux 的 Python 侧说它的话。`ev = "draw"` 是渲染器的通道，其余取值渲染器整帧跳过——但今天没有别的取值在用：`reflux:hello`／`reflux:nav` 走上行的 `Outflow`，同一条线上分家（见「协议」）。
- **I7——封闭性与跨字段语义归 reflux，不归渲染器。** accrete 刻意不拒未知字段（旧帧兼容），生产端写错的字段名在那边是静默丢弃；「越域即拒」与「这个槽名／事件名／字段名声明过吗」只能落在 reflux 这一侧：生成的 SDK、服务端的入站校验、门（旧形态的 `payload` 键那条随 `payload` 一起退场）。**代价写明**：绕过 SDK 手写 JSON 直连渲染器的生产者没有任何封闭性——这是选「兼容行为优先」要认的账。

每个客户端只有一个写者：只有生产者写结构与数据。渲染器写它自己的局部态；生产者的处理器只改生产者这边的业务数据。

「渲染器永不动」要成立靠上面几件一起：帧定义只有一套、封闭性与跨字段语义在框架侧、词表封闭在类型里。带开放组件注册表的渲染器无论文档怎么写都是移动靶。为加一个组件而改一处类型、重导一次 schema 的那点摩擦，是刻意留的。

## 协议

传输是每会话一条 WebSocket，帧定义用 fluxen 的那套（它的 `content` crate）：下行 `Message { ev, sender, created, content }`（`sender` 就是我们的会话 id），上行 `Outflow { event, id?, data }`。信封不另立——一个 socket 上两套帧定义就是永久的一致税。

```
下行  {"ev": "draw", "sender": "<session>", "content": [{"action": "create", ...}]}
上行  {"event": "chat.send", "id": "row-42", "data": {"value": "…"}}
```

各 action 的字段形状以 `content` crate 为准（`Influx` / `InfluxTmpl` / `AppendOp` / `RemoveOp` / `PatchOp` / `InjectOp`）——**取它那八个，逐字，不留翻译层**（2026-10-17 裁决；逐条转换与代价见「操作」）。

- `ev` 是帧的类别。渲染器只消费 `draw`，其余取值**整帧跳过**——所以别的类别是留着的通道，加一类不必改信封形状；必填，缺失即拒帧。**但今天没有第二类**：`reflux:hello` 与 `reflux:nav` 都是上行帧（`Outflow` 的 `data` 是自由的，正合它们的载荷），它们要的东西由下行的一次 `draw` 回答，存活走协议层 ping。别指望往 `Message` 里塞框架载荷——它的字段全是定型的：要框架的下行帧就得先给那个信封加字段，那是改 fluxen（见「Why Not」）。
- 一回合一批而不是一操作一帧：一个处理器可能改动多处，成批才让一个回合在客户端看来是一个整体（`content` 本来就是 `OneOrMany`）。
- 编解码两边都认 JSON 与 CBOR（`ActiveCodec`）：先只走 JSON，帧本来就小（操作是增量、结构低频），第二种编码意味着第二份要和第一份同步的 schema；什么时候切由实测定，不由预感定。
- 下行帧不直接写 socket：每会话一条**有界出帧队列**，由它自己的写线程送出（写是唯一会被客户端拖住的一步，慢客户端只能拖住它自己那条线程）。队列满时丢中间帧并标记陈旧，排空后用一帧 `create` 重同步——细节见「失败模式」。

### 连接与握手

连接建立后**先由客户端 runtime 上行一帧 hello，生产者才开始发结构**：

```
{"event": "reflux:hello", "data": {"path": "/settings"}}
```

连接那一刻生产者还不知道客户端站在哪条路径上，先发会先出一棵错的树、再改一次。hello 交上的那件只有客户端知道的事就是当前路径——深链由此成立。

已落地（T4）：壳连上 `/ws` 即发 hello，生产者的应用在收到它时发出这个会话的首帧（一帧里既有 `create`，也可以顺手把视图要读的槽播下去）。hello 不带任何凭证：会话就是连接（见「会话与身份」）。

传输落地的形状：`reflux/channel.py`（HTTP 升级 + 文本帧编解码，stdlib）、`reflux/events.py`（事件名注册表）、`reflux/app.py`（伺服壳 + `/ws` + 注册表；一个连接一个 session）。

### 组件形状

粗组件的字段少而封闭：

```
{"type": "input",                     // 取自组件表
 "id": null,                          // 节点身份：键控列表的行、需要跨结构变动存活的节点
 "attrs": {"kind": "password", "placeholder": "密码"},   // 该组件自己的属性白名单
 "bind": {"source": "login.form", "event": "login.submit", "payload": ["value"]},
 "children": []}
```

- **`attrs` 是每类型的白名单**（accrete 那份的形状），取值是枚举或受限值域；reflux 的 profile 在它上面选与设默认。生产端见不到自由 class 字符串——变体的闭集合由 profile 落成 class 令牌；accrete 的线上是允许 class 的，收窄落在 profile 与 SDK 上（见「组件词表」）。本节示例仍是退休前线上的那份形状，换成 accrete 的节点形状随 M1 落。
- **`bind` 是组件与事件流之间的唯一接口**：`source` 是读（数据槽的名字，组件盯着它），`event` 是写（事件名，组件上行它），`payload` 声明这次上行要带上哪几件本地态（`value`、`selection`、`fields`…）。I4 的落点就在这一行：**要什么状态，组件自己声明带上去。** 换成 accrete 的 `bind` 之后这条线这样落：读槽 = `kind: source`，上行落点 = `kind: event`（表单里 = `kind: field` + `field`），`fire` 与 `payload` 随旧规格退场——**什么时候发、发什么由组件实现定**，不再是生产者声明的契约。代价写明：生产者想知道某个事件什么时候响，只能去读渲染器的实现（旧形态里「时机是契约的一部分」这条让位给「组件是现成的」）。
  - `source` 怎么用由组件语义定：叶把它当自己的 `primary` 画出来（`text` 的文字、`image` 的 src……），带值的输入把它当自己的值，容器把槽值当子节点挂（一轮数组＝列表槽，单个节点＝片段）。槽还没写过时回退到构造时的属性值，所以「先出结构、再补数据」和「一帧里都发」都成立。
  - 上行**时机**写在规格的 `fire` 里（`⊆ fire_events`：`change` / `submit` / `click`）：接受 `event` 的组件必须声明它，不接受的一个也不声明。时机是契约的一部分——生产者不该靠读壳的实现才知道自己声明的事件什么时候响；`change` 是提交/失焦语义，于是「每次按键一次往返」在构造上就不存在。accrete 侧能上行事件的只有 input／textarea／select 与 `form` 的 submit，`click` 那一档的落点见「组件词表」。
- **上行帧是 `{event, id, data}`**：`id` 取认领该事件的那个节点自己的 id（不是祖先）——行的身份要上行，就把行的 id 给行里那个交互节点；`data` 是组件随事件送上来的那份本地态（旧形态按 `payload` 声明的顺序取，`payload` 已退场——送什么由组件定）。
- **不需要 id 也能更新**：数据的地址是槽名，不是节点名。id 只为身份存在（行身份、跨结构变动的存活）。

### 操作：accrete 的八个，逐字

| action | 形状 | 落点与语义 |
|--------|------|------|
| `create` | `Influx{event, data}` | 整体替换那棵唯一的 layout（首屏、翻页、重同步）。`event` 在这个 action 里不被读，线上仍要写（`Influx.event` 是必填字段）——我们写 `""` |
| `set` | `Influx{event, data}` | 整体替换一个具名数据槽里的节点 |
| `append` | `AppendOp{event, position, data}` | 往列表槽 `event` 加一行；`position` 见下 |
| `remove` | `RemoveOp{event, id}` | 从列表槽 `event` 删掉 `id` 那一行 |
| `patch` | `PatchOp{event, id?, path, op, value}` | 按 JSON Pointer 改值；`op` 是 `replace` 或 `append`（字符串续写／数组追加） |
| `inject` | `InjectOp{slot, event?, id?, data}` | 远程写 vals 平面——像页面自己 emit 了一次本地事件，订阅方分不出是谁写的；同值短路 |
| `tmpl` | `InfluxTmpl{name, data}` | 注册一张 `{{key}}` 槽位替换表，渲染器展开节点时用 |
| `empty` | — | 什么都不做 |

**`position` 的算术**（一处定义：`content::append_index`）：`0` = 末尾（默认，等于旧协议的 `"end"`，线上省略这个字段）；`+n` 从**尾**往内数（`+1` = 最后一个之前，`+len` = 头部）；`-n` 从**头**往内数（`-1` = 头部）。域外**拒收，不夹取**——夹取会把行放到调用方没要求的位置，那是静默降级。方向是刻意的：索引一律从这次操作自己的锚定端往内数。

**四个平面，各有各的寻址**（取代旧协议的「一个 JSON Pointer 走进 tree / slots 两个面」）：

- **layout 根**：`patch{event: "", path, …}`——`path` 与旧协议的 `/tree/…` 是同一种指针，只是少了那层 `tree` 前缀（根就是那棵树）。
- **具名数据槽**：`set` 换掉整个槽，`patch{event: <槽名>}` 改槽里的一个位置——旧协议的 `/slots/<名>`。
- **列表槽的行**：`append` / `remove` / `patch{event: <槽名>, id: <行 id>}`——按**身份**改一行。这比旧协议强：旧协议只能按位置进树，插一行之后位置就飘了。
- **vals 平面**：`inject`——服务端写前端本地态。旧协议没有这个能力。

**旧四个逐条换成什么**（代价一并写明）：

- `create(root, title?)` → `create{event: "", data: root}`。`title` 没有落点，见本节末。
- `patch(path, value)` → `patch{event: …, path: …, op: "replace", value}`。顺带白得 `op: "append"`——流式续写不用再自己拼整串。
- `remove(path, id?)` → `remove{event: <列表槽>, id}`：行的删除本来就按身份，与旧协议同。
- `insert(列表槽, anchor, node)` → `append{event, position, data}`：anchor 从「`{"index": n}` / `{"id": s}` / `"end"`」换成「从哪一端数第几个」。**代价**：按 id 锚定的插入没有了，生产端得自己数；数错了那一帧被拒（大声，不会放到没要求的位置）。判据：单写者——生产端本来就清楚自己往里放了什么，这个数它算得出来。
- `insert(某个节点的 children 数组, …)` → `patch{event: "", path: "/children/…/children", op: "replace", value: […]}`：整段数组重写。**代价**：结构数组里插一格要重写那一段（O(n) 字节）。判据：结构低频，这条不违背「服务端不画界面」。

`move` 仍然刻意缺席：重排表达为 `patch` 换掉那段数组，代价是每次重排 O(段长)；加操作的触发条件是实测（T11），不是预感。

**浏览器标题没有线上落点**：`create` 的 `title` 在 accrete 的信封里无处可放（`Message` 的字段全是定型的，fluxen 全仓也没有 `document.title` 的机制）。落法（2026-10-17 裁决）：生产端在页面里放一个**保留 id** 的节点，内容就是标题（`placeholder` 会把节点 id 落到 DOM 上）；框架那段客户端 runtime 每次渲染后读它、写 `document.title`。判据与「runtime 拥有 URL」是同一条——标题和 URL 一样是浏览器的事实，归 runtime 管。代价说白：每页多一个节点（由 reflux 自己的样式表藏起来），runtime 会去 DOM 里看一眼。要第一等的线上字段就得给 `Message` 加字段，那是改 fluxen 的帧定义，没走这条路。

### 数据槽

- **单项槽**：`bind.source = "login.form"` 指一个具名数据槽，值可以是一份数据，也可以是组件树的片段——生产者的 `set` 换掉整个槽，`patch{event: <槽名>}` 改槽里的一个位置。
- **列表槽**：`rack` 一类组件读的是列表槽，行按 `id` 合并；生产者的 `append` / `remove` 按行来，没有 `id` 的行退化为按位置渲染（合法，但丢掉跨插入的行身份）。
- **vals 平面**：`inject` 写的具名值槽，与上面两者分开——事件数据不是展示形态（所以它是裸 `Value`，不是节点）。
- 渲染器侧的槽是**按路径的惰性订阅**：写某个槽只惊动读它的那些组件，不广播全表。这是「增量」从线上延伸到客户端内部的那一段。

### 事件名就是寻址契约

`event` 不是标签，是**这次交互该送到哪个处理器**的地址。三条纪律：

- 生产者侧的注册表是唯一权威：未注册的事件名**拒收**并计数，绝不尝试动态派发（`getattr(模块, 线上传来的名字)` 是任意属性调用面，运行前也无法校验）。
- 保留前缀 `reflux:` 归框架（`reflux:hello`／`reflux:nav` 由客户端 runtime 上行，两个保留 id 也在这个前缀下）；生产者把处理器注册到保留前缀上，启动即报错。
- 事件名可打印、可核对（`reflux events` 列出注册表）。名字里不塞业务参数——参数在 `data` 里。

## 组件词表：accrete 的类型，加一份 profile

词表的单一来源是 accrete 的类型（I5）：30 个根变体，每个变体自己的属性白名单、闭枚举。渲染器对**全部 30 个**都有实现（`ui_leptos` 的 30 个分派函数，`template_` 是个空 view），所以 profile 从整个集合里挑，不存在「声明了没实现」的坑。

profile 是 reflux 侧的一份**可读数据**——里面没有类型定义（类型来自 schema），只记三件事：

- **选**：哪些类型进应用面。
- **默认**：哪个属性值是默认。
- **收**：生产端见不到自由 class——变体收成闭集合，由 profile 低成 class 令牌（accrete 的线上允许 class，令牌就是 `attrs.class` 里的那些字符串）。

现有那 21 项（`spec/components.json`）与它不是包含关系：同名 8 项——form / rack / input / textarea / select / button / image / text；另外 13 项是 reflux 自己的词，逐个落成：

| 我们这一项 | 落点 |
|---|---|
| stack | `case`（默认竖排；`attrs.horizontal` 决定要不要 `col` 类） |
| row | `case` + `attrs.horizontal` |
| card | `case` + class 令牌（`tone` 三个值是令牌） |
| field | 不是类型：表单字段是 `form` 的 `bind.field` 寻址，标签与提示是同级 `text` |
| option | 不是类型：`select` 的选项来自它绑的列表槽的行，行 `id` 即键 |
| checkbox | `input` + `bind.type = bool`（渲染器据此给 `type="checkbox"`） |
| switch | 同 checkbox，只差 class 令牌；`label` 降成同级 `text`，`disabled` 那边没有字段、只有 class |
| heading | `text` + class 令牌（`level` 1–3 是令牌） |
| badge | `text` + class 令牌（`tone` 五个值是令牌） |
| code | `text` + `attrs.format = "md"`：GFM 出围栏代码块，样式在 `main.css` 的 `pre`/`code` |
| empty | 表达得出来，但落点要核：`placeholder` 的空槽分支是现成的相反规则（槽非空渲染那个节点、空渲染 `children`），不过它看的是 data 平面，列表空不空它看不见 |
| progress | 不进词表：纯展示、无交互，自绘部件走 `canvas` 的模块通道 |
| link | **退场，不补替代**（2026-10-17 裁决）：accrete 没有锚点类型，渲染器也从不导航；词表里能上行事件的只有 input／textarea／select 与 `form` 的 submit。所以 link 这个元素没有了，锚点语义（中键或修饰键新开标签、悬停看地址、右键复制链接）也没有。「点一下就把事件送上去」还剩一扇门——canvas 的模块通道（模块拿到 `host.send`，与表单 submit 同一条上行腿），代价是应用自己写那个 ES 模块。页内导航怎么做见「客户端 runtime」 |

同名那 8 项里还有两处不能按名字对：`button` 在那边只在 form 里当提交器（`bind["value"]` 不是 `Submit` 就渲染成空 div）；`input` 的类型来自 `bind.type`（`JsType`），不在属性上。

accrete 那侧比我们宽的另外 22 项（case / placeholder / chart / diagram / canvas / editor / float / layer / portal / fold / popup / svg / group / path / pages / table 一族 / template）是 fluxen 自己的语义面（版面容器与栅格、图层与模态、挂载外部模块、表格、SVG）；进不进应用面是 profile 的选择，不是缺项。

每个类型声明四件事，前两件在类型里，后两件在 profile 里：

- **本地态**：它内部维护什么（输入缓冲、是否展开、当前选中、滚动位置）——渲染器的。
- **绑定**：读哪个槽、上行哪个事件、上行时带哪些本地态——形状来自 accrete 的 `bind`。
- **上行时机**：在哪类事件上上行——渲染器与 profile 一起定。
- **属性**：类型自己的白名单（闭枚举、受限值域）；变体的闭集合收在 profile 里、落成 class 令牌。

属性侧有几处是这次裁决认下的落空（逐项核过 accrete 的属性空间）：`placeholder`（input／textarea）与 `disabled`（input／textarea／select／button／form）在那边没有字段，只有 class；`input.kind` 里的 email／search 没有对应（`JsType` 只有 bool／number／text／password／button／submit）；`textarea.rows`、`form.submit_label`、`rack` 的 density／empty_text／follow 同样没有字段（accrete 的 rack 只有 `scroll`）；`image.fit`、`text.wrap`、`text`／`button`／`badge` 的 size／tone／variant 都走 class 令牌。这些不构成加词表的理由——要么是外观（令牌），要么是渲染器的行为细节；真装不下的在落 profile 时逐条列出来。**还有一处落空不是属性而是机制**：我们的 `payload`（组件声明这次上行要带哪几件本地态）在那边没有位置——送什么由组件自己定（输入送它的值、表单送它收集到的字段），所以构造器不提供这个参数。

**词表的厚度就是交互逻辑的表达力。** 这个模型的复杂度不在服务端，在这里：应用里凡是「依赖状态的界面行为」，只有两个去处——落进某个组件的声明式语义（本地态 + 事件 + 变体），或者走一次事件上行交给生产者。所以加组件时的判据是「有哪类交互逻辑现在无处表达」，不是「界面还缺哪种元素」。

*为什么不给生产端自由 class／工具类字符串*：那等于把样式决策交回生产者，外形开始漂移，生成的界面不再可穷举，还得在客户端挂一个运行时 CSS 合成器。样式归类型与 profile，生产者只选类型与变体——换来的是确定性，代价是生产者的样式自由。accrete 的线上是允许 class 的，所以这条纪律落在 profile 与 SDK 上、不落在类型里：生产者见到的是一份闭集合，落到线上才是令牌。（逃生门留作开放问题，要有实测需求才开。）

## 生产者（各语言 SDK）

SDK 的职责只有三件：

- **生成结构**：把宿主语言的写法变成组件树与结构操作。
- **绑定**：把组件挂到事件名与数据槽上。
- **收事件、改数据、推回槽**：事件到达时跑处理器，把变化的数据 `patch` 进槽（必要时才动结构）。

处理器收到的是一整帧：`handler(session, frame)`，`frame.data` 就是组件送上来的那份（`Outflow` 的 `data`），`frame.event`／`frame.id` 是要送达的名字与行身份。会话用它这一回合的改动组一帧发出（`session.draw(*ops)`）——一个处理器改了几处，客户端看到的就是一个回合。

**SDK 的构造器与类型由 schema 与 profile 生成**，不由人手写——这是 I5 的落点，也是「换个语言就能用」的前提。落地的形状（Python 是第一个）：`schema/accrete.schema.json` 是 fluxen 导出物的快照（`tools/sync_schema.py` 在对拍；它要那个仓，所以不进默认门），`profile/profile.json` 是 reflux 的选择与默认；`tools/gen_sdk.py` 用它调 datamodel-codegen 出类型层、再对着实测修形，构造器面按 schema 的类型与 profile 的选择生成，落在 `reflux/sdk/`（`types.py`、`builders.py` 生成；`_parse.py`、`profile.py` 手写）。**为什么要修形**：那份原始输出把 30 个臂里 18 个的 `type` 判别式丢了（实测 `{"type":"float"}` 验成 `Case`），`bind` 压成了 `dict[str, Any]`，`PositionAttr` 的扁平键整批消失——修形是对着实测的，不是口味。门：`python3 tools/gen_sdk.py --check` 与 `python3 -m unittest tests.test_sdk_generated`。

### 写入层（Python 侧）

`ui` 是规格词表的寻址层：`ui.<组件>(...)` 就是那个组件的生成构造器（真实签名、真实默认值、仍在 `make` 这个边界上校验）。它加的是**形状**——子节点走位置参数（列表会被摊开，视图由循环拼出来是常态），其余关键字与线上同名。它不加词汇：一个导入、不遮蔽内建 `input`、认错一个名字就报出封闭词表。

`ops` 是帧的构造器：accrete 的八个 action 加 `draw`（一个回合＝一帧）。每个都在边界上校验自己的形状——不是 JSON Pointer 的路径、域外的 `position`、不是节点的节点，都在发送前就大声；这些东西在渲染器那边只是 `warn`（不带计数），所以必须在我们这一侧发现。两个模块的职责不重叠（`ops` 的名字与词表的名字不许相交，有测试钉着）。

*可选的便利层*：SDK 可以额外提供「声明一个视图、由框架重渲染 + diff 算出操作」的写法，用于「结构本身依赖数据」的场合。但它是便利层，不是每事件的路径：默认路径是处理器直接推那几条数据操作，服务端不参与画界面。

*为什么不让服务端持有界面状态*：那会把每会话的成本顶到「一棵树 × 每事件 O(树)」的量级（实测：750 节点树重建 + diff 0.37 ms/回合/会话，100 会话各 50 事件/秒吃满两核），并且造出影子状态——同一个值在服务端和壳各有一份，谁是真的一直要讨论。适用边界不装作不存在：复杂表单、多步流程、**服务端渲染下一步**这类场景确实需要服务端看到状态，那时的正形是**让组件把这份状态随事件带上去**（送什么由组件定，见「组件形状」），不是让服务端私自持有。

## 客户端 runtime

框架自己的一小段 JS，挂在渲染器那个包旁边——一个文件，不自己渲染，也不进那个包。它管的全部是**浏览器的事实**：渲染器驮不了、却只有页面这个环境能写的那几件。

- **URL 是它的。** 生产者在树里声明当前路径（见下面的两条约定），runtime 每次渲染后（只读地看 DOM 的变更，不碰节点）把它镜像进地址栏——URL 真的变了才 `pushState`（停在当前路径不堆历史条目）。`popstate`（后退/前进）与地址栏手输是两件不同的事：前者上行一帧 `reflux:nav`（`data` 只有 `path`），后者是整页加载（重新连接、hello 带上那条路径）。
- **标题也是它的**：同一个机制，换一个标记。
- **握手**：连上即上行 `reflux:hello`（`data` 只有 `path`）——连接那一刻生产者还不知道客户端站在哪条路径上，先发会先出一棵错的树（见「连接与握手」）。它自己不持 socket：上行走渲染器在页面上发布的那个把手（见「实施计划」M1.1），runtime 是它的调用者，不是第二条连接。

**它读树的两条约定**（这是它与渲染器之间唯一的接口）：两个**保留 id** 的节点——`reflux:path`（当前路径）与 `reflux:title`（标题）。`placeholder` 会把节点 id 落到 DOM 上，所以这两个标记就是普通节点；它们由 SDK 的糖生成（名字与签名在写 SDK 时定），应用不直接写这个约定；两个 id 由 reflux 自己的样式表藏起来。

*为什么是 DOM 而不是帧*：下行信封（`Message`）没有自由字段，框架的载荷在帧里放不下；而这两件本来就是浏览器的、本来就只有 runtime 能写。判据与「标题和 URL 一样是浏览器的事实」是同一条。**代价写明**：生产者漏写标记（或写错）时，地址栏与标题停在旧值——runtime 只镜像，不猜；这是「失败模式」里的一条，门对着它断言。

**同源锚点这个形态没有了**（accrete 没有带 URL 的类型，见「组件词表」）：所以没有「拦截点击」这回事——没有东西可拦，四类放行（修饰键、中键、`external`、跨源）随之退场。要在页面上放一个「点一下就做事」的东西，走 canvas 的模块通道（模块拿到 `host.send`，与表单 submit 同一条上行腿）；要让一次选择或一次提交把用户带到别处，则是生产者的处理器回一帧新结构与新的路径标记。

## 壳（SolidJS）

下面各小节描述**当前仍在跑**的那份实现（T0–T6 的门对着它跑通），也是裁决退场的那一份。迁移时按这个分工拆：渲染（解释器、组件分派、属性写入、样式）交渲染器与 `ui-assets` 的样式框架；分派表与节点校验（`components.generated.js`、`validate.js`）随「词表来源」一起退场，换成 accrete 的类型加服务端入站校验；导航与握手（`nav.js`、`channel.js` 里那部分）成为框架自己的客户端 runtime；本地态那条边界（缓冲区不被无关写擦掉、上行时机由组件声明）是渲染器要继承的契约，不是可以省掉的一层。

### 资产与加载

钉死版本、自托管，由伺服应用的那个进程一并伺服：

- `index.html`：静态，由库提供，不由应用作者提供。伺服进程把**页面路径**（没有扩展名、也不是一个真实文件）也交给它——深链与刷新靠这条：客户端先起来，再问生产者那条路径是什么页面（见「路由」）。有扩展名的路径仍按文件处理，缺文件就是 404，绝不回一坨 HTML 冒充模块。
- SolidJS 的 ESM（core / web / store / h）按钉死版本 vendored，用**原生 import map** 加载。
- 一份 `VERSIONS`，记下锁定的上游版本与升版流程。

无编译靠 Solid 的两个免编译入口：`solid-js/h`（hyperscript，即 builder 模式）与 `solid-js/html`（模板字面量），都是 ESM，配 import map 直接跑；代价是响应式要显式写取值函数——壳本来就是手写响应式，正合适。

*为什么不用 CDN URL*：部署不再密闭——运行时依赖第三方主机、版本在脚下漂移、断网或纯本地场景直接失败。自托管代价是一个目录，换掉的是整类「什么都没改它却坏了」。
*为什么不用打包器*：它给消费方加一步，并摧毁本设计赖以成立的静态资产属性。import map 是平台自带的机制，不需要工具。

### 解释器

```
apply(frame):
  if frame.ev != "draw": log; return
  batch(() => for op in frame.ops: apply_op(op))
```

结构放在 `createStore` 里（Solid 的代理 store，按路径追踪读取），在某个路径上的写只通知读了该路径的表达式——细粒度更新由此成立，不需要虚拟 DOM，也不需要客户端 diff。整批操作在 `batch()` 里应用，多操作帧在 DOM 看来是原子的。

### 组件分派

按 `type` 静态派发到组件表里每一项对应的实现——**一张写在代码里的表，不是运行时可注册的注册表**：没有 `register()`，加组件是改这张表（并同步规格与各 SDK），那点摩擦是刻意留的：它是词表不被稀释的机制。Rust/WASM 下封闭枚举是约束下的自然解；JS 能开放，所以这里的封闭**靠纪律与测试维持**，不靠类型系统——这是选 JS 要认的账。机制落在两处：构建期的 `spec == implementations` 相等断言，运行期的 `unsupported` 计数兜底（真漏了是可见的一块占位加一个计数，不是静默空白）。

### 本地态与响应式边界

组件的本地态是壳里的信号；从槽读到的数据经组件的渲染表达式订阅。两条边界：

- 本地态**永不上行**，除非组件声明了 `payload` 要带它。一次按键的光标位置不该依赖一次往返。
- 上行时机由组件决定（提交、失焦、节流、显式按钮），不由框架猜——这是杀掉「每次按键往返」的机制。
- 输入类组件的缓冲是这条边界的样板：只要用户还在编辑，壳就不覆盖已经敲进去的内容；失焦之后重新由槽值驱动。一次无关的槽写不该擦掉正在输入的字。

### 事件

壳在根节点按 `fire_events` 逐类挂一个委托监听器：插入与删除不产生逐节点监听器的翻动。命中规则是**最近的认领者拥有这次交互**——从事件目标向上找到第一个 `fire` 含该事件类型的组件宿主，所以容器不会吃掉子组件的事件；这个宿主没有 `bind.event` 就什么都不发（它可能只是在看一个槽）。`submit` 由壳 `preventDefault`：提交是壳的职责，浏览器不该因此导航。

上行帧是 `{event, id, data}`。`id` 取**认领该事件的那个节点自己的 id**，不是某个祖先的——行的身份要上行，就把行的 id 给行里的那个交互节点。`data` 按 `payload` 声明的顺序逐个取本地态，不多不少（声明是契约，不是提示）。本地态从 DOM 事实读：`input.value`、`select.value`、`checkbox.checked`、表单的 `fields`（子树里声明了 `source` 的字段，按 `source` 为键——槽名就是字段的地址，所以一次提交带上它持有的全部字段）、`rack.scrollTop`。

### 属性写入

走**每组件白名单**加取值域（枚举、字符串、数字、布尔、受检 URL）。永不接受线上设置：`on*` 属性、`srcdoc`、`formaction`、任何非 http(s) 的 URL scheme。生产者受信，但线上内容仍是需要解析的输入；白名单把注入面压到零，同时充当 SDK 的生成依据。

### 样式

样式是壳的（§组件词表）：生产者只选组件与变体，见不到 class 字符串。落地的形状沿 fluxen 那份样式框架
（`crates/ui-assets/assets/main.css`）：**层序先声明，再写各层**——`theme / base / layout / element / custom / style`。

- `theme` 是令牌层：颜色用 `light-dark()` 随 `color-scheme` 切换；圆角、间距刻度和边框合成
  （`--rx-border` 由宽／线型／色三件合成）都在这里。
- `base` 是原生元素默认与页面本身；`layout` 是布局原语（stack / row / rack / form 的 flex 与间距刻度）；
  `element` 是那几个自有原生元素外观的组件（input / textarea / select / checkbox / switch / button / link）；
  `style` 是外形、组件 chrome 与变体角色。
- 变体走两条通道，壳都不写内联样式：**枚举 → data 属性 → 层里改指一个令牌**
  （`[data-tone="danger"] { --rx-role: var(--rx-tone-danger) }`，组件读 `--rx-role`，于是「角色」只声明一次，
  这是 fluxen `.accent.border` 那个写法的同构）；**数据值 → 自定义属性**（进度条读 `--rx-value`）。
- `custom` 层占着位、没有文件：宿主侧的样式逃生门仍是开放问题，层位先留好——将来那一步不必重开这个文件的层序。

### 导航

（这一节是退休形态的记录：**拦截同源锚点**、四类放行、壳写 history。目标形态里没有锚点可拦——见「客户端 runtime」，地址栏由 runtime 从树里的路径标记镜像。）

同源链接点击、前进后退、地址栏改动都由壳处理：取路径、写 history、发 `reflux:nav` 上行，等生产者的新结构回来。这是壳唯一写 URL 的地方——漏掉它，任何导航都退化成整页刷新，细粒度全部作废。

落地的判据（四类**不拦截**，交给浏览器）：带修饰键的点击（Ctrl/Cmd/Shift/Alt——用户要的是新标签页）、中键、生产者标了 `external` 的链接、以及 href 不是同源的。其余同源点击一律拦截：`preventDefault`，URL 真的变了才 `pushState`（点当前路径不堆历史条目），然后上行 `reflux:nav`。`popstate`（后退/前进）是同一个请求，只是不写 history；地址栏手输等于一次整页加载，壳重新连接、hello 带上那条路径（T4 已落）。

`reflux:nav` 的 `data` 只有 `path`：路由契约是路径，查询串留在地址栏（浏览器写的那份）——`?x=1` 不进线上是**协议范围**，不是漏项。

## 路由

路由在生产者侧声明（由 SDK 提供形状），注册进一张按路径为键的表——匹配器只认那张表。

```python
@route("/blog/{slug}", title="文章")
def post(session, match): ...        # 返回结构（组件树）；match 是一次匹配：路径、参数、来自哪条声明

@route("/")                          # 别名：同一个处理器挂第二个路径，叠一个装饰器
@route("/posts")
def post_index(session, match): ...
```

- 路径挂在处理器上，声明与实现同处一地——没有一张要和代码对齐的中心清单，也就没有那份清单可以漂移的地方。
- 注册器就是按路径为键的字典：同一条路由登记两次不必靠查重规则去拦，撞键即报错。
- 装饰器是一次注册调用的语法糖（`route(path, handler=...)`）：装饰器形态把处理器原样交回（叠两个装饰器就是别名），显式形态交回那条 `Route`（循环里成组生成时用得上）。
- **路径语法两个记号**：`{name}` 吃一段（**不吃空段**，空段是尾兜底的事）；`{name:path}` 收尾兜底，吃剩下的全部、**含空段**（`/docs`、`/docs/`、`/docs/a/b` 都进它）。转换器只有 `path` 一个，要加第二个得先论证。
- **发现是 import 的事**：`discover(*packages)` 导入你给的一个或多个包并遍历其子模块，某模块导入失败即启动错误，跳过它不在选项里。**没有任何东西从文件名派生**——文件名只影响 import，不影响 URL；表里的"来源模块"是处理器写在哪，不是框架猜出来的。
- **匹配按一条明确的择优键**（四个词，先到先判）：`静态段数` 多者胜 → `不含尾兜底` 者胜 → `段数` 多者胜 → `捕获段数` 少者胜。静态压过 `{name}`、`{name}` 压过 `{name:path}` 都是它的推论。注册顺序不参与判定——结果不能取决于 import 顺序。
- 同一路径注册两次即报错，不做「后写覆盖」；两条**能匹配同一条具体路径**且**择优键相同**的形状（如 `/x/{a}` 与 `/{b}/y` 之于 `/x/y`），启动即报错——歧义不靠注册顺序解决，顺序是运气不是意图。键不同就让规则决定输赢（`/x/y` 与 `/x/{a}` 都匹配 `/x/y`，静态多的那条赢）。
- 请求路径按**逐段**百分号解码（`%2F` 不许裂段），静态段与捕获段都按解码后的文本比较。
- `layout` 是一个普通 callable：`layout(session, match, page)`，页面由它自己安排（没有 outlet、没有嵌套机制）。`Match.resolve(session)` 把两者组成这一页的结构——导航那一侧只需要调它。
- `python3 -m reflux.cli routes <package>` 打印注册表（路径、来源模块、元数据字段）；`reflux events` 那一栏等 T9 的「从包装配出应用」约定（打印事件表要先能找到那个注册表，路由表不需要——它只有一张）。

**路由切换就是客户端 runtime 请求一次新结构**（`reflux:nav` → 匹配 → `create`，回来的那帧里还带新的路径标记）：结构是低频的，这条不违背「服务端不画界面」。深链也一样靠 hello 带路径，代价说白：没有服务端渲染，深链要多等一次连接往返才出界面——是延迟，不是错误。

落地的那一侧是应用的一个钩子：`app.page(session, path)` 给出一页——**一个节点，或这一帧的操作表**（后者是应用顺手播种它要读的槽的方式）。默认实现就是路由表解析；单页应用覆盖它，连路由都不必声明，`App.view` 这个中间名因此退休。匹配不到、又没有 `{rest:path}` 兜底时，框架回**内置 404 结构**（用写入层搭的一个 spec 合法节点）——想自己 404 就注册一条尾兜底路由，它是一次普通匹配，按规则赢。

深链与刷新还要求**伺服进程把页面路径交给客户端**：路径没有扩展名、也不是一个真实文件时，回 `index.html`（客户端起来之后再问生产者那条路径是什么页面）。没有这条，`/blog/x` 会 404 到客户端都起不来，整类深链直接不成立。

## 会话与身份

一个连接一个会话：会话持有**路由、身份、它要推送数据的目标**——不持有界面状态，也不持有整棵组件树（那是壳的）。一百个会话就是一百份小记录。

- **会话就是连接**：起于连接打开，止于断线或判死。没有跨连接的身份凭证——socket 本身就是持续连接，状态活在连接里；「让刷新接回同一个会话」是把无状态世界的道具搬进来，而这里没有那个问题（刷新回到初始是正常表现，见本节末）。所以 hello 只带路径。
- **身份是连接上的一个事件**（对外提供服务的部署才需要）：连接无条件建立，随后由应用注册的 `login` 事件把身份挂到会话上。框架不预设鉴权，也没有任何连接前的前置条件——凭证不进 URL、不进 cookie、不进日志。
- **心跳与判死**：WS 长连接会留半开连接——客户端不见了、TCP 没关，断线事件永远不会来。按固定间隔（默认 10s）发协议层 ping，超过阈值（默认 30s）没有入站活动就判死：告知、**关掉 socket**（只关描述符唤不醒阻塞在 `read` 上的线程，`shutdown` 才行）、从表里删。会话表只在断线与判死两处删，且按连接身份删——没有线程能删掉不属于它的会话；判死那条先出表、再记账，所以同一个会话不会被计两次（`dead` 与 `reclaimed` 是两种不同的收场）。
- 会话表与计数在应用上（`issued` / `reclaimed` / `dead`），要看现在的会话用 `App.live()`（快照）；日志里每个生命周期带会话 id（短随机，只为可读，不是安全边界）。

界面工作态不在服务端，所以**刷新后界面回到初始**是这套设计的正常表现，不是 bug。要跨刷新保留，走显式机制（组件把关键值随事件带上、由生产者存进它的业务数据），不用 localStorage 偷偷兜。

## 失败模式

| 情况 | 行为 | 归属 |
|------|------|------|
| 指针未命中／命中非容器／补丁后形状不合法 | 丢掉该操作、带路径记日志；同帧其余照常应用 | 渲染器（`warn`，不带计数） |
| 帧早于 `create` 到达 | 新形态里没有「还没有树」这个状态：渲染器起手就有一棵空 layout，未命中的 patch 就是未命中（上一行） | 渲染器 |
| 未知组件类型／属性／取值域不合法 | 构造期就拒（`parse` 抛），服务端入站校验再拦一道，会话保留；**绕过 SDK 直连的生产者没有这两道**——accrete 刻意不拒未知字段，那边是静默丢弃 | SDK ＋ 服务端（渲染器不管） |
| 一帧的操作数超过 `max_ops_per_frame` | 整帧拒收、计数——上限来自我们这一侧（一处定义：SDK 的 `draw` 边界大声，服务端入站校验再拦一道）；渲染器没有这个上限 | SDK ＋ 服务端 |
| 未注册的事件名 | 拒收、计数、记日志；绝不动态派发 | 服务端（注册表在生产者侧） |
| 事件载荷缺少声明的字段 | **随 `payload` 一起作废**：新形态里送什么由组件自己定（输入送它的值、表单送它收集到的字段），我们不声明也不校验 | — |
| 处理器抛异常 | 带事件名与 traceback 记日志；会话保留；客户端停在最后一次成功应用的状态 | 服务端 |
| 生产者侧非法结构（属性不合法、一段数组里行 id 重复） | 发送之前就报错——在边界上大声，绝不把缺陷静默带到客户端；同一个列表槽里 `append` 一个已有的行 id，渲染器也会拒（`warn`）；跨帧的行身份冲突只有应用认识那份列表，归应用 | SDK（大声）＋ 渲染器（`warn`）＋ 应用 |
| 慢客户端 | 出帧队列**在入队时**有界（`App(outbox=256)`）；溢出丢中间帧（留首帧与最新）、标记会话陈旧、计数；应用的 flusher 在队列排空且陈旧时用一帧 `create` 重同步 | 服务端 |
| 半开连接（客户端消失但 TCP 没关） | 心跳超时判死并回收；会话表不涨成泄漏 | 服务端 |
| 树里没有路径标记／标记与地址栏不一致 | 地址栏与标题**只镜像，不猜**：没有标记就停在旧值；唯一写者是生产者，所以「标记 == 地址栏」是一条要断言的不变量 | 客户端 runtime（镜像）＋ 生产者（声明）；门对着它断言 |
| 导航到不存在的路径 | 注册了 `{rest:path}` 兜底就用它，否则回内置 404 结构；不换会话、不改身份、不做重定向（地址栏仍是用户去的那条，`session.path` 跟着客户端走） | 服务端（路由）＋ 客户端 runtime（只负责发请求） |
| 同一路径注册两次／并列形状歧义 | 注册时或启动时即报错 | 服务端，启动时 |
| 发现根里的模块导入失败 | 启动即报错，不跳过——跳过等于让一部分路由静默消失 | 服务端，启动时 |

计数只归我们这一侧：渲染器的失败是 `tracing::warn`（一行日志，不带计数），所以每一条要在我们这里留下数字的降级——入站校验、路由、会话、出帧队列——都得计数并带足身份记日志（会话、路径、操作、事件名）。绕过 SDK 的生产者只剩渲染器的 `warn` 与我们的入站校验这两道，这条写明：静默降级不是选项，但有一道边界的可观测性在别人手里，这是选「帧定义只有一套」要认的账。

## Why Not

- **让客户端 runtime 去改渲染器画出来的 DOM 造锚点**（MutationObserver + 把标记节点重写成 `<a>`，好把新标签页那些语义保住）：那是与渲染器的响应式对着干——它下一次重建就把包装抹掉，症状是「有时能新开、有时不能」这种最难查的一类。锚点语义的代价该由词表承（accrete 里得有一个带 URL 的类型），不该由一个事后改 DOM 的 runtime 偷偷补。
- **让 reflux 自带一个 wasm 入口**（自己建 transport、自己发布上行把手，渲染器一行不改）：入口就变成两份，`#main`／codec／URL 的协商要同步两处，渲染器那边以后的改进（重连、编码）到不了 reflux；而页面级上行把手与 canvas 拿到的 `host.send` 是同一件事——渲染器本来就在给宿主的 JS 递上行函数。代价认下：fluxen 多一个宿主 API（`Message` 不动，这不是线）。
- **给 fluxen 的 `Message` 加一个框架字段**（好让框架有下行帧，或让 `create` 直接带上标题）：帧定义只有一套是这套设计的地基，往里塞字段等于把 reflux 的需求搬进那个包——它得跟着维护，每个消费方都得认这个字段；而我们真正需要的那件事（标题）是浏览器的事实，runtime 读 DOM 就够了。判据同「词表不往外长」：不是把来源变宽，而是在它上面找现成的落点。
- **把我们的四个操作留成线上的一层翻译**（`create/patch/insert/remove` 与 accrete 的八个并存，收发时来回转）：第二份近义词就是要消掉的税，而且它会慢慢和对面漂开——`append` 的 `position` 算术、`patch` 的平面路由、`inject` 的同值短路都会在翻译里被抹平成近似。代价认下：`insert` 的按 id 锚定与结构数组里插一格都要换写法（见「操作」）。
- **服务端持有界面状态、每事件重渲染 + diff**：这是最初那版的形态，被两件事否掉——每事件 O(树) 的成本要乘上会话数（实测 0.37 ms/回合/会话；100 会话各 50 事件/秒 = 两核），以及影子状态（同一个值两边各一份，谁是真的一直要讨论）。**边界**：复杂表单、多步流程、服务端渲染下一步确实需要服务端看到状态——正形是让组件把这份状态随事件带上去，不是让服务端私自持有。这条是「深思熟虑的拒绝」，不是「做不到」。
- **生产者生成 HTML/JS（iframe 或 eval）**：线上是代码、没有 schema、按构造就是一个 XSS 引擎。它是让「壳永不动」字面成立的唯一办法，也正是那个字面读法是个陷阱的原因。
- **每回合发整棵树，让浏览器 diff**：带宽 O(树)，且 diff 落在最慢的一侧。
- **壳里放虚拟 DOM**：按构造冗余——操作已经是增量。
- **细粒度原语（div/span 上行）+ 自由 class 字符串**：把元素映射、样式、可访问性、本地行为全推给生产者，壳退化成 HTML 解释器，词表也不再可穷举。粗组件正是为免掉这一层存在的。
- **运行时组件注册表**（自注册的 widget）：线上永远不是封闭 schema、SDK 无法对着它校验，「壳永不动」也就变得不可证伪。
- **运行时 CSS 合成（工具类引擎）**：样式决策回到生产者手上、外形漂移、多一个运行时合成器；换成组件自带的变体枚举。
- **SDK 手写自己的组件表**：N 个语言 N 份词表，必然漂移（I5）；SDK 由规格生成。
- **写视图的语法走 `with` 块（栈式 builder）**：它让「当前的父容器」变成隐式状态——一个影子父节点，而且一个「往当前容器追加」的辅助函数就无法返回自己那棵子树了。子节点走位置参数是显式的，组合（`ui.stack(*parts)`）也就不需要任何约定。
- **给界面写一套文本记法**：多一套要和规格同步的语法，而规格已经是机器可读的那一份；宿主语言本身就是记法（循环、条件、函数都在手边）。
- **统一的 `ui("stack", ...)`**：把规格派生的签名（`text(value, *, tone=…)`）全丢掉，错字只能等到边界才知道。`ui.<组件>` 保留真实签名。
- **把状态藏在 localStorage 里当作「刷新恢复」**：那是绕过 I4 的影子状态，两端各有一份且不会同时更新——要保留就显式带上去、存在生产者的业务数据里。
- **文件名即 URL**（Nuxt 式页面目录）：把「文件叫什么」变成对外路径的单一来源，于是别名、成组生成的路由、单条路由的元数据覆写全都无处可写；它买到的只是「常见情形不写路径」，而装饰器同样不另建清单。文件名该管的只有 import。
- **手写一张中心路由清单**（`urls.py` 式）：每加一个视图动两处，且清单与视图空间上分离——读视图的人还得跳回去找它的路径。装饰器填的还是同一张表，位置就在声明处。
- **表里放字符串引用**（`"mymod:view"`）：晚期失败的间接——表里有一条路由指向已经不存在的视图，要等有人访问才炸；装饰器上挂的是 callable，导入期就解析。
- **路由判断写在业务代码里**（一个处理器里按路径分支）：表不再可打印、可校验，404 与匹配优先级藏进 `if` 链。
- **壳里再放一张路由表**：两张表必然漂移，而只有生产者知道有哪些视图——匹配必须在它那侧。
- **一次上齐路由全家桶**（可选段、命名路由、嵌套 outlet、中间件、数据 loader）：词表越大越难学、越难校验；每项都要有实测出的需求才进（触发条件见「开放问题」）。
- **两个词表各自维护**（旧形态写的「规格另立，不强行共用」）：两份手写词表必然漂移，而 fluxen 那侧的类型加 schema 导出已经能当单一来源；另立买到的只是「不必对齐」的短暂自由，代价是永久的一致税，也让「任意语言生产者」这个卖点停在一句口号上。
- **让 accrete 为 reflux 长出组件与枚举属性**（把那 13 项、以及 variant／tone／size 这类闭集合加进那 30 个根变体）：单一来源不是把来源变宽，而是在那套词表上做选择——宽出来的每一分都是渲染器要多实现、多维护的面，而变体的闭集合本来就可以收在 profile 里。判据是归属：外观与默认是框架的策略（profile），词表是渲染器的能力（accrete 的类型）。代价认下：变体这一层的封闭退成 profile 的数据 + 生成器的门 + 服务端入站校验，不再靠编译期类型。
- **把渲染器再写一份（JS 载体）**：这不是风格问题——动态类型里没有地方放「封闭词表」这个不变量，它只能落成数据加运行时断言，那些类型检测与防御性断言是载体决定的。判据是结果：本仓的门抓到的失败全是**静默**的那一类（`render()` 只求值一次、取值函数、深读、假绿 wait、深链 404），静默正是类型本该拦下的；AI 改动场景下差距更大，编译器是默认开着的那层验证。
- **以「静态资产、无构建」当 JS 壳的结构性理由**：一条都站不住。wasm 产物同样是静态资产（维护者构建一次、钉版本伺服，消费方不编译）；任意语言的生产者本来就靠 accrete 的 JSON，schema 导出加生成补齐了类型那一侧。剩下的只有「用 JS 写渲染器」本身。
- **以「JS 门槛低、便于外部参与」为理由**：实测不成立，代码没有变得可读，这条作废。
- **把资产体积与跨边界开销当判据**：显式不作判据——宁可更慢。

## 开放问题

留成带明确触发条件的问题，不是无限期的待办：

- 第二个语言的 SDK 先做哪个？触发：Python SDK 跑通后，选一个宿主语言里已有真实需求的——它是「规格是产品」这条的验收。
- 组件的属性白名单里要不要开一个受控的样式逃生门？触发：容器级微调的需求在多个应用里反复出现，且变体枚举装不下。
- 重定向要不要进协议？别名叠一个装饰器就够；重定向要壳改地址栏（那是壳的职责），需要一个像 `create` 那样小的机制。触发：真的出现必须换地址的场景（登录跳转、路径迁移）。
- 路由要不要中间件与数据 loader？触发：同一段鉴权或取数逻辑在三个以上视图里重复出现。
- 组件本地态要不要跨路由存活？触发：真实应用里出现「切走再回来表单没了」的抱怨，而 `payload` 声明带不上去。
- 规格要不要版本协商（hello 里带 SDK 版本，壳按版本选行为）？触发：出现第一个已部署的旧 SDK。
- 上行的时机要不要按**实例**声明？触发：真出现一个需要逐键上行的检索输入；届时给 `input` 加一个时机枚举（现在时机按组件类型写在规格的 `fire` 里，一律是提交/失焦语义）。
- 输入框要不要清除控件？触发：真有清除需求。叶级替换元素驮不了 chrome——要做就得给 `input` 一个统一外壳，那是一次形状变更而不是加一个属性；规格里的 `input.clearable` 已在 T4 按这条收窄掉（「壳无法兑现的属性是规格缺陷」，不是实现里的 TODO）。
- `move` 值不值得进词表？触发：200 行以上列表的重排代价实测（T11）。
- 组件表长到多大就不再对生成器可学？不是阻塞项；重审 I3 的触发是一张不再能放在一屏里的表。
- **操作集**（已定，2026-10-17）：取 accrete 的八个逐字，四个平面各有各的寻址，逐条转换与代价见「操作」；解释器与门随 M1 一起搬过去。
- **页内导航与 click 上行**（已定，2026-10-17）：link 退场、锚点语义不要；URL 与标题由客户端 runtime 从树里的两个保留 id 镜像；「点一下就做事」只剩 canvas 的模块通道。做法与代价见「客户端 runtime」与「组件词表」。
- **SDK 生成的后处理**（已定，2026-10-17）：不是「按 `const` 事后改名」——那 12 个匿名臂是被**展开**了，改名会和已有的同名类（`Chart`／`Text` 这些）撞车；修法是补 `type` 判别式、把根联合重建为 discriminated union、`bind` 收成 `dict[str, Bind]`、`PositionAttr` 的扁平键补齐。落在 `tools/gen_sdk.py` 的后处理里，形状见「生产者」。
- **框架帧的 `ev` 取值**（已定，2026-10-17）：今天没有第二类——`reflux:hello`／`reflux:nav` 都走上行的 `Outflow`，回答是一次 `draw`，存活走协议层 ping。别的取值是留着的通道（渲染器整帧跳过），但 `Message` 里放不下载荷：真要一类下行框架帧，得先给那个信封加字段（见「Why Not」）。

## 实施计划

原子任务，每个挂一道验证门槛。没有「把框架接起来」这种任务。

- **T0——骨架与零工具链证明。** 仓库布局：`spec/`、`shell/`（vendored 资产 + `VERSIONS`）、`reflux/`（Python SDK 与壳伺服）、`tools/`（生成器与各道门）、`tests/`、`docs/`。门槛：demo 进程伺服壳；无头浏览器加载它时**零控制台错误、零外部网络请求**（两条都在 CDP 上断言）。
- **T1——规格。** 组件表、属性白名单与取值域、绑定形状、操作集、事件保留前缀，写成机器可读的一份（JSON Schema 或等价的 IDL）。门槛：规格能编译出两张派生物——壳的分派表与 SDK 的构造器——且三者互不漂移有一致性测试（改规格则两边同时变，diff 可见）。
- **T2——壳的 store 与解释器。** 四个操作、路径寻址、槽订阅，暂不渲染。门槛：经 CDP 应用一段脚本化操作流、读回 store 快照；未知路径的操作被丢弃并计数；整批操作的原子性（观察者看不到半个回合）。
- **T3——组件分派与本地态。**（已落地）规格里那 21 个组件全部有实现，每个只读自己要画的字段、带变体枚举与本地态。门槛：变更计数——改一处槽只重算读它的组件，兄弟节点不重渲染；本地态（输入缓冲）在一次无关的 store 写之后仍在；规格与实现两张表相等；未知组件与越域取值整帧拒收。
- **T4——绑定与事件。**（已落地）`source`（叶取值、容器取子节点，含列表槽）、`event`／`payload` 与规格里的 `fire`（上行时机）、根节点的委托监听、`/ws` 通道与 hello、上行帧 `{event, id, data}`、生产者侧的注册表与未注册事件名拒收；顺带落了写入层（`ui`／`ops`）与示例应用 `reflux/demo_app.py`。门槛：真实浏览器里的端到端测试（输入回显、列表增删、表单一次提交多个字段），并断言上行帧的 `data` 与 `payload` 声明逐字一致。
- **T5——路由。**（已落地）装饰器与注册器、发现（导入给定包并遍历子模块）、择优键与并列歧义检测（启动即报错）、`{name:path}` 尾兜底、逐段百分号解码、`layout` 与 `Match.resolve`、`python3 -m reflux.cli routes`。门槛：表驱动测试（重复路径、并列歧义、`{name:path}` 收尾、百分号转义）；`handler` 与 `layout` 都是 callable（写错是导入期错误，不是首次访问才炸）；换一种 import 顺序注册同一组路由，匹配结果逐例一致。
- **T6——导航。**（已落地）壳侧链接拦截（带修饰键/中键/`external`/跨源四类放行）、`popstate`、history 写入、hello 带路径；生产者侧 `reflux:nav` → 匹配 → `create`，应用侧 `app.page(session, path)` 钩子，匹配不到回内置 404（有 `{rest:path}` 就用它）；伺服进程把无扩展名、无对应文件的页面路径交给壳（深链与刷新成立的前提）。门槛：点链接与前进后退各一次，地址栏／界面／服务端路由三者一致；未知路径走 404 结构；冷启动直接打开 `/blog/x` 落在该页。**目标形态里没有锚点**（见「客户端 runtime」）：M1 把这条门改写成「路径标记 → 地址栏镜像 + 后退前进 + 深链 + 404」，四类放行随锚点退场。
- **T7——会话与心跳。**（已落地）会话即连接：连接打开即登记、断线即回收；心跳线程按默认 10s 发协议层 ping、30s 没有入站活动即判死并回收（关 socket 让阻塞的读线程退出）；计数 issued / reclaimed / dead，看现在的会话用 `App.live()`。门槛：一次刷新后表里只剩一个会话（旧连接被回收）；客户端不发 FIN 就消失时判死并回收、表归零，且那条算 `dead` 而不是 `reclaimed`。没有 token 这一层——「跨连接复用」随「会话即连接」一起作废，「伪造 token」那条门槛随之退休。
- **T8——故障注入。** 坏帧（未知 action、未知路径、未知组件、未注册事件名、超大批次、重复行 id、慢客户端、地址栏与路径标记不一致）各自产生「失败模式」里规定的行为，且会话存活。
- **T9——Python SDK。**（先决：M1）由 schema 与 profile 生成的构造器，加上那一层命名与手感（见「开放问题」的生成后处理一条）；事件注册；`@route`；处理器签名 `handler(session, frame)`；出帧走每会话单队列（顺序由构造保证）。门槛：demo 应用（`reflux/demo_app.py` 是 T4 留下的种子）只用 SDK 写出来，能跑通输入／列表／表单三类交互；导航那一类按「客户端 runtime」的镜像机制测——没有锚点可点，翻页靠一次选择或提交。
- **T10——第二个语言的 SDK（最小）。** 只生成构造器与上行，证明「规格是产品」不是口号。门槛：同一个 demo 结构在第二语言里写出来，线上帧与 Python 版逐字一致（同一份规格）。
- **T11——测量。** 每回合帧字节数、壳侧重渲染范围（DOM 变更计数）、首屏与资产体积、100 会话 × N 事件/秒的服务端 CPU。门槛：数字记进 `docs/PERF.md`；本文档里每一条性能断言要么有测量，要么被显式标为未测量。

### 迁移：M1 拆成六件

迁移期**两个页面并存**：退休的壳继续伺服 `/`（T0–T8 的旧门对着它跑），新页面在 `/__next/`、它的资产在 `/static/`——每一轮落地时它自己的门同轮改到新侧，全套不留红窗。页面里的资源用源站绝对路径，所以 M1.6 把 `/__next/` 提到 `/` 时页面一行不改，只改挂载表。判据：迁移中任何一次落地，全套门都能跑绿；两页同夹具，T11 的数字直接可比。

- **M1.1——入口把手。** 渲染器今天自己建 transport（`mount()` 里 `WsTransport::new`，路径写死 `/channel`，codec 默认 CBOR），整仓没有一处 `#[wasm_bindgen]`——页面上没有可调的把手，runtime 的 hello 与 nav 就没有出口；而把 `?codec=json` 挂在页面 URL 上，会让「标记 == 地址栏」这条断言自带噪音。落法：渲染器入口多读 `#main` 的 `data-codec` / `data-path`（`data-host`／`data-token` 已有先例），挂载后发布**一个页面级上行把手**——与 canvas 拿到的 `host.send` 同形状、同一条 uplink；连接还没打开时调用也不会丢（`emit` 是 future，gloo 的 `Sink::poll_ready` 在 `readyState == 0` 时挂起、`open` 时唤醒），把手只负责 `spawn_local` 它。reflux 的页面带 `data-codec="json"`，路径留 `/ws`。**装配必须留在 `mount_to` 的闭包里**：`Ctx::new` 用 Leptos 的 executor，早于它调用会 panic（实测：把 transport 与 `Ctx` 提到 mount 之前，页面白屏、`#main` 空着、控制台一条 `spawn_local before a global executor was initialized`）。门槛：真 chromium 打开页面，连接落在 `/ws` 且帧是 JSON；从页面里调一次那个把手，生产者收到一帧 `{event, id?, data}`。
- **M1.2——资产与伺服。**（已落地 2026-10-19）`www/` 是页面树、`www/static/` 是它的资产树，两个挂载：`/__next/` → `www/`、`/static/` → `www/static/`。页面是**静态文件**：`#main` 带 `data-codec="json"` / `data-path="/ws"`；资源一律从源站绝对路径取（`/static/…`——相对路径会被深链解析到深链目录底下，实测 `/__next/blog/a/post` 就是这么白屏的）；js/wasm 的名字从 `versions.json` 读，页面里不写死（trunk 的产物名带内容哈希）。`versions.json` 记渲染器构建的 rev 与逐文件 sha256／大小，升版＝`trunk build --release` → 拷四件 → 刷哈希 → 门重跑；它既是资产清单，也是 `tests/test_page.py` 与门的对拍对象。reflux 的样式表现在只有一件：藏两个标记（用 `[id="reflux:path"]` 这类属性选择器，冒号让 `#id` 很别扭）；profile 的 class 令牌随词表接线（M1.5）。门槛：T0 改写（`gate_t0_next.py`）——零 console error、零外部请求、请求清单恰好等于钉住的那几件、每件的 sha256 与 manifest 一致（**过 HTTP 取**，能抓到挂载错位）、`/` 仍是壳、深链回页面。
- **M1.3——客户端 runtime。** 两个标记的镜像（路径真变才 `pushState`，`document.title` 同理；标记用 `getElementById` 读——`text` 把 id 塞进 class 列表，只有 `placeholder` 一类把 id 落到 DOM 上）、hello 带 `location.pathname`、`popstate` 上行 `reflux:nav`；地址栏手输靠的是**没有代码**：浏览器整页加载。它不认识树、不认识帧、不碰 socket。门槛：T6 改写——地址栏与标题分别等于两个标记；后退一次 → 一帧 nav → 回来的帧带新标记；无标记的页面停在旧值（不猜）；冷启动 `/blog/x` 的 hello 带那条路径；未知路径落 404。
- **M1.4——服务端入站校验。** 落在应用收帧处：八个 action 的形状、事件名注册表、上行 `id`、`max_ops`、行 id 唯一，以及 profile 的闭集合（类型／属性／取值域）——未知字段拒收由 schema 与 profile 生成，不手写第二份。一条边界写明：「这个槽名声明过吗」在入站判不了（判它就得让会话持着它发出去的树，那是影子状态），这条留在 SDK 的构造期。门槛：离线表驱动（每类拒一次、一帧合法通过、计数与日志字段齐全），加一条绕过 SDK 的手写坏帧端到端。
- **M1.5——交互门重对。** T2（壳的 store 与解释器）与 T3（分派表与本地态）退场——它们是壳的内部，渲染器那边有实现；换成两条端到端：八个 action 各自的落点、profile 里每个类型至少画出来一次。T4 改写：`input` 失焦上行、`form` 一次提交带上 `fields`、`id` 认领规则；`payload` 那几条断言删掉。T8 的坏帧清单以入站为准（渲染器的降级只 `warn`，不计数）。门槛：改写后的 T4′／T8′，加 T5／T7 的离线门，全套绿。
- **M1.6——退场。** 删 `spec/`、`shell/*`（vendored SolidJS、壳 CSS、壳侧生成物）、`tools/gen.py` 里生成壳分派表的那一半、对着规格与壳写的用例；`/__next` 提到 `/`；`gen_sdk.py --check` 留作词表门。门槛：`rg 'spec/components.json|shell/js|SolidJS'` 零命中，全套绿。

## 词汇

规格层的词：`component`（粗组件）、`attrs`（每组件白名单）、`bind`（accrete 的绑定表：读槽 / 上行落点 / 表单字段，见「组件形状」）、`slot`（单项槽、列表槽、vals 平面）、`action`（accrete 的八个操作：`create` / `set` / `append` / `remove` / `patch` / `inject` / `tmpl` / `empty`；我们的四个是退场形态的词）、`path`、`id`、`route`（一条声明：路径 pattern、处理器、layout、元数据）、`match`（一次匹配：具体路径、参数、它来自哪条 route）、`page`（一条路径上的结构：路由解析出来的，或应用自己给的）、保留前缀 `reflux:`（`reflux:hello`／`reflux:nav`，以及两个保留 id `reflux:path`／`reflux:title`——runtime 从树里读那两个标记）、`SDK`、`schema`（accrete 的类型导出的那一份，词表的对外形态）。产物侧的词：`渲染器`（fluxen 的渲染运行时，那个包）、`客户端 runtime`（框架自己那一小段：握手、URL 与标题的镜像）、`profile`（reflux 在 accrete 词表上的选择与默认）、`入站校验`（服务端那一道：封闭性与跨字段语义的落点）、`session`（路由＋身份＋推送目标）、`handler`（处理器）、`frame`（上行帧 `{event, id, data}`）、`channel`（一条 WS 连接）、`app`（页面钩子＋通道＋事件名注册表）、`ui`／`ops`（写入层：节点与帧的构造器）。`shell`、`spec` 与 `fire`／`payload` 是退场形态的词，只在描述现状时用。别处不再另造同义词。
